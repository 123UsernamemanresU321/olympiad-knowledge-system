# Olympiad Hub App

This frontend renders the Olympiad knowledge base directly from the repository `content/` folder and local progress data generated by real user interactions.

## Local Development

1. Install dependencies:

```bash
npm ci
```

2. Start the app:

```bash
npm run dev
```

## Environment Variables

Copy `.env.example` to `.env` for local development.

- `VITE_BASE_PATH`: Public base path for the deployed app. Use `/` locally.
- `VITE_SUPABASE_URL`: Your Supabase project URL.
- `VITE_SUPABASE_ANON_KEY`: Your Supabase anon key. This is the only Supabase key that may be exposed to the browser bundle.
- `VITE_SUPABASE_PROGRESS_TABLE`: REST table name used by the optional progress sync module.
- `VITE_SUPABASE_PROGRESS_SYNC`: Set to `true` only after you have configured a table and RLS policy that is safe for your auth model.

## Supabase Notes

- Do not put a `service_role` key into any `VITE_*` variable. GitHub Pages is a static deployment, so anything under `VITE_*` is compiled into the client bundle.
- The app keeps progress in local storage by default.
- Optional Supabase progress sync is env-gated and disabled unless `VITE_SUPABASE_PROGRESS_SYNC=true`.
- Secure browser writes still require an auth/RLS setup on your Supabase project. This repo does not ship an unsafe open-write policy.

## GitHub Pages Deployment

The workflow at `.github/workflows/deploy-pages.yml` builds `app/` and deploys `app/dist` to GitHub Pages.

Configure these GitHub repository secrets before enabling the workflow:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`

Recommended repository variable:

- `VITE_SUPABASE_PROGRESS_SYNC`

The workflow automatically sets `VITE_BASE_PATH` to the repository name so asset URLs work on GitHub Pages project sites.
